2026-11-20 在掌机与 Windows Qt 绿色版之间重新推流。真机三档均由播放器自动发现，画质选 SPAN 2×（DirectML FP16）、补帧关闭、缓冲 100 ms。先验证启动器，再在用户确认进入游戏后分别采集约 45 秒。下面的赛道窗口以实际游戏画面标记，避开启动器、黑屏过场和标题菜单。

此表覆盖各次抓包，与上表赛道窗口分开计算。网卡抓包工具报告本地捕获丢弃为零。分片缺失以 PC 端已经见到的视频序号为分母；三轮另有 22、16、37 个区间内序号完全未见。掌机编码数与完成发送数也存在差额，单凭 PC 抓包无法定位这些序号消失在哪一环。三轮掌机报告的发送错误增量均为零。每次降码率附近都观察到数据分片缺失。1.00 MB/s 初次降档前只有约半秒实际视频，无法评价持续满档时的画质。

三个档位均收到有效的双声道音频，Qt 没有报告解码错误。一次连续 5.001 秒的赛道样本有 1,023 个完整音频块，无补零，左右声道不同，均未出现满幅削波。较长采集仍有缺块和时间轴空缺；这些数据不能替代对扬声器输出的听感判断。

## 同一段真机数据的 PC 效果对照

取本次 0.80/24 采集的赛道，以会话首个媒体包为零点回放第 6–18 秒，另留 3 秒预热、2 秒收尾。按原到达间隔送入同一台 PC 上的 1.2.8 测试播放器，关闭自动发现并固定回环地址。该项使用 Qt 离屏画布，以便给不同效果相同输入；真机表使用 Windows 正常窗口。

| PC 画质 / 补帧 | 实际后端 | 上屏原生更新绘制数 | 其中增强图 | 额外绘制的上屏 / 下屏中间帧 |
| --- | --- | ---: | ---: | ---: |
| SPAN 2× | DirectML FP16 | 272 | 240 | 0 / 0 |
| Real-ESRGAN AnimeVideo-v3 2× | DirectML | 271 | 52 | 0 / 0 |
| FBCNN 原尺寸去块 | 本机可选 TensorRT FP16 | 270 | 270 | 0 / 0 |
| SPAN 2× + RIFE | DirectML FP16 + 本机 TensorRT FP16 | 272 | 246 | 179 / 0 |

四组都收到 272 次原生上屏更新。RIFE 的 179 次中间帧绘制都只更新了上屏，下屏仍有 267 次原生更新绘制。目前 Qt 使用上屏时间戳触发补帧。上屏先到可配上一张旧下屏，后到的下屏在同一上屏时间戳内无法单独触发新任务。能从日志完整还原的 153 个已绘制中间帧任务，其起止下屏序号都相同。这个限制发生在 PC 补帧调度，原生下屏仍在接收和绘制。[Qt 补帧任务排队](../qt/pipeline.cpp)

## 本次使用建议

这条链路上优先用 **0.80 MB/s、30 FPS** 玩赛车，想以 2× 看运动画面可选 SPAN。更看重单帧细节时可选 24 FPS，观察 **ⓘ 直播性能** 的实际码率、JPEG Q 和收齐 FPS。1.00 MB/s 在本次游戏里触发了降档，没有持续兑现更高的源画质。

测试结束后按原保存设置重新打开了项目绿色版（FBCNN、补帧关、0.80 MB/s、30 FPS、开启声音）。重连核验期间收到 2,201 个视频数据分片、505 个音频包，PC 向掌机发送了 9 份接收反馈。原始录包、逐帧绘制日志、部署备份和五秒立体声样本位于本机项目的 `live/build/device-128-qa/`。
